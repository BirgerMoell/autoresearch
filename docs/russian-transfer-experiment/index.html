Russian Inclusion Transfer Experiment

A small-GPU, autoresearch-style probe of whether adding Russian to a production-like multilingual allocation helps related European languages. The answer in this proxy is yes, with the clearest gains in Cyrillic Slavic languages.

What Was Tested

The experiment parses a large language/source allocation table, extracts every language-coded row, collapses those token targets into per-language sampling weights, and trains small byte-level language models with and without Russian.

Russian was absent from the provided allocation. The comparison adds rus_Cyrl with the same collapsed target mass as Ukrainian: 44,680m tokens. This is then tested two ways: at the same total training budget, and with a slightly larger budget proportional to the added Russian mass.

Core result: adding Russian improves the Slavic target average by 0.43% at the same total token budget and by 0.61% when Russian is treated as extra data.

Why This Is Evidence For Including Russian

Transfer Appears Where Expected

The strongest same-budget gains are Russian, Ukrainian, Bulgarian, Macedonian, and Serbian. That pattern is consistent with useful overlap in script, morphology, byte statistics, names, loanwords, and multilingual document conventions.

The Fixed-Budget Arm Matters

At fixed budget, Russian has to compete with all other languages. The Slavic target average still improves, so the result is not only a "more tokens always helps" story.

The Extra-Budget Arm Is A Sanity Check

When Russian is added as extra data, performance improves more broadly. That says Russian is useful data in this proxy, not merely a source of favorable random variation.

Trade-Offs Are Visible

Some Latin-script languages move slightly worse in the same-budget arm because their sampling mass is diluted. This is exactly why inclusion should be measured rather than argued abstractly.

Target-Language Results

The target set was chosen to focus on languages where Russian might plausibly help: Bulgarian, Ukrainian, Macedonian, Serbian, Polish, Czech, Slovak, Slovene, Croatian, and Bosnian.

Experimental Setup

The model is deliberately small: a 6-layer, 6-head, 384-dimensional byte-level causal Transformer trained at sequence length 256 and batch size 64. Each base condition ran 1,200 steps across two seeds. The extra-budget condition ran 1,219 steps, proportional to the extra Russian language mass.

Each language used 12 MB of training bytes and 2 MB of validation bytes built by streaming parquet batches from one FinePDFs-Edu shard per language. Peak GPU memory was only 1.55 GB on an NVIDIA L4.

Scope And Caveats

This is a cheap transfer probe, not a definitive downstream benchmark. It matches language allocation weights using local proxy text. It does not train on the full production Megatron/HPLT/Nemotron corpora, and it does not use the production tokenizer.

Rows without a language suffix, such as generic CLM, StarCoder, math, OLMo, and generic Nemotron rows, are not used as language sampling weights here. They are real production-mix mass, but they do not isolate the narrow question of adding a Russian language slice.

The local proxy lacked data for als_Latn, gle_Latn, kat_Geor, nno_Latn, and sqi_Latn. All available language-coded weights were included.
