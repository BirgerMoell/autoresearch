Small-GPU controlled data-mix experiment

Russian improves a Slavic-language proxy metric in this run

We tested whether adding Russian to a production-like multilingual language allocation helps related European languages. The evaluation is held-out next-byte prediction on proxy text, not a downstream task.

Result

Under a fixed training budget, adding Russian improved the Slavic target-language average by 0.43% BPB relative to the no-Russian condition.

Abstract for ML engineers

This is a controlled, low-cost transfer probe. We hold model, optimizer, evaluation protocol, seed count, training bytes, and architecture constant, and vary only whether Russian appears in the language sampling mixture.

The input was a proposed multilingual data allocation table. We parsed every language-coded row, collapsed rows into language-level target masses, normalized those masses to sampling weights, then constructed three conditions: no Russian, Russian inserted at fixed total budget, and Russian inserted with proportional extra budget.

The main metric is held-out bits per byte (BPB) averaged over ten Slavic target languages. Lower is better. The fixed-budget Russian condition improved from 3.0576 to 3.0444 BPB.

Claim supported by this page: Russian is useful enough in this proxy to justify inclusion and more serious production-scale testing. This is not a claim about downstream QA, translation, instruction following, or final model quality.

What the evaluation actually does

The eval is language-model validation loss on held-out proxy text. It is not a task benchmark, and it has no prompts or labels beyond the next byte in the text itself.

Validation source FinePDFs-Edu one-shard proxy text
Held out per language 2 MB validation bytes
Eval sample Random 256-byte chunks
Metric BPB = cross-entropy / log(2)

For a validation chunk of length 256, the model receives bytes 1..255 and predicts bytes 2..256. We do this over 40 batches per language and average the result. If a model has lower BPB on Ukrainian, for example, it is less surprised by held-out Ukrainian proxy text. 

for language in eval_languages:
    chunks = sample(validation_bytes[language])
    logits = model(chunks[:, :-1])
    target = chunks[:, 1:]
    bpb[language] = cross_entropy(logits, target) / log(2)
This answers a narrow question: does Russian in the train mixture improve next-byte modeling of held-out text in related languages? It does not directly measure QA, translation, instruction following, or factual reasoning.

Controlled design

The goal is to isolate the effect of a Russian language slice while keeping the model and evaluation constant.

Independent variable

Training mixture condition: no Russian, Russian fixed budget, Russian extra budget.

Controls

Same byte model, architecture, optimizer, train bytes per language, validation construction, eval batches, and seeds.

Primary endpoint

Mean BPB over ten Slavic target languages: bg, uk, mk, sr, pl, cs, sk, sl, hr, bs.

Mixture construction

The provided allocation table contains source/language rows such as hplt-3.0/megatron-lm/ukr_Cyrl. The experiment uses those language-coded rows to build sampling weights.

Rows are parsed with a language-code suffix pattern like xxx_Script. Target token counts are summed by local language code. Russian was absent from the allocation, so the Russian condition inserts rus_Cyrl at the same collapsed target mass as Ukrainian: 44,680m tokens in the original allocation scale.

The local proxy covered 33 non-Russian languages from the language-coded mix. Russian was then added as the 34th evaluation language.

Generic rows without language suffixes, such as CLM, StarCoder, OLMo, math, and generic Nemotron rows, are not used for language sampling in this proxy. They matter for the full production mixture, but do not isolate the Russian language-slice question.

Interpretation and limitations

This is useful evidence, but it is scoped evidence. It should guide a stronger production experiment rather than replace one.

What the result supports

Russian improves next-byte prediction on the Slavic target average in a fixed-budget proxy. That is evidence against excluding Russian by default for purely technical reasons.

What it does not prove

It does not prove downstream benchmark improvements, final production model quality, or the optimal amount of Russian.

Best next experiment

Repeat with the production tokenizer, actual production shards, a longer training budget, and downstream Ukrainian/Bulgarian/ Serbian/Macedonian evaluations.

Data caveat: the run uses FinePDFs-Edu one-shard proxy data because the GPU did not have the full production corpora. The experiment matches language allocation weights where local proxy data is available.
