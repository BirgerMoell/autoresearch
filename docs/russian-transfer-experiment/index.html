Plain-language answer: Russian helped in this proxy.

Should Russian be included in a multilingual training mix?

We ran a small, controlled experiment to test a practical data-mix question: if a model already trains on many European languages, does adding Russian help nearby languages, or does it simply take space away from them?

What changed?

We trained the same small byte-level language model three ways: without Russian, with Russian at the same total training budget, and with Russian as extra data.

The experiment in one paragraph

We took the proposed multilingual allocation table, extracted the language-specific token targets, and used those targets as sampling weights. Then we added Russian at the same target mass as Ukrainian and trained tiny models to see whether validation loss improved on related languages.

The key comparison is the same-budget run. It keeps the total training work fixed. That means Russian has to be useful enough to make up for slightly reducing the sampling share of every other language. In this run, it did: the Slavic target average improved.

How to read the result: BPB means bits per byte. Lower BPB means the model predicts the validation text better. A negative delta is therefore an improvement.

Headline result

Target average covers Bulgarian, Ukrainian, Macedonian, Serbian, Polish, Czech, Slovak, Slovene, Croatian, and Bosnian.

What exactly was evaluated?

The evaluation is language-model validation loss on held-out proxy text, not a downstream task benchmark.

For every available language, the script builds two byte datasets from FinePDFs-Edu one-shard samples: 12 MB for training and 2 MB held out for validation. During evaluation, the trained model sees random 256-byte chunks from the validation split and is scored on how well it predicts the next byte.

There are no task labels, prompts, multiple-choice questions, or human judgments in this evaluation. The "label" for each byte is simply the next byte from the same held-out text. The eval asks: given this language's validation text, how surprised is the model by the next byte?

So the question answered here is: after training with or without Russian, does the model predict held-out text in related languages better? In this proxy, yes. The Slavic target average improved when Russian was included.

Evaluation loop

1. Pick a language Evaluate each language separately, using its own held-out validation bytes.
2. Sample text chunks Draw random 256-byte chunks from the 2 MB validation split.
3. Predict shifted bytes The input is bytes 1..255. The target is bytes 2..256 from the same text.
4. Average BPB Cross-entropy is converted to bits per byte and averaged over 40 batches.

This is not a direct evaluation of question answering, translation, instruction following, or factual reasoning. It is a cheap signal of whether the language model learned a better distribution for each language. 

for language in eval_languages:
    chunks = sample(validation_bytes[language])
    prediction = model(chunks[:, :-1])
    target = chunks[:, 1:]
    bpb[language] = cross_entropy(prediction, target) / log(2)

What was actually done?

The experiment is intentionally simple. It does not try to train a production model. It asks a narrow question cheaply: does adding a Russian slice create measurable transfer in a multilingual language model?

1
Start with the proposed mix
The input is a long table of target token counts such as HPLT, FinePDFs, Nemotron-CC-Opus, and Tower language slices.
2
Extract language rows
Rows ending in codes like ukr_Cyrl or pol_Latn are grouped into language totals.
3
Add a Russian condition
Russian was not in the table, so rus_Cyrl was added with the same collapsed token target as Ukrainian.
4
Train tiny models
The same model is trained without Russian, with Russian at fixed budget, and with Russian as a small extra budget.
5
Measure prediction quality
Each model is evaluated on held-out text in 34 languages. Lower BPB means the model predicts the bytes better.

Why there are two Russian comparisons

Adding a language can mean two different things. You can keep the total token budget fixed, which forces every language to give up a tiny bit of sampling share. Or you can add the new language as extra data, increasing the total budget.

The fixed-budget comparison is stricter. If it improves, that is stronger evidence that Russian is useful for the target languages rather than just useful because the model saw more total data.

  • Same total budget: 19.7M training tokens in both arms.
  • Extra budget: 20.0M training tokens, matching the added Russian mass.
  • Russian insertion: 44,680m target tokens in the original allocation scale.

What kind of model was trained?

The model is deliberately small so the experiment can run quickly on a small GPU. It is not meant to be a final model. It is a measuring instrument: if language transfer exists, even a small model should show a directional signal.

Byte-level language model

The model reads text as UTF-8 bytes. It learns to predict the next byte. This avoids tokenizer complications and makes the experiment quick, although a production run should repeat the test with the production tokenizer.

Data pipeline

The GPU machine did not have the full production corpora, so we used one FinePDFs-Edu shard per available language as proxy text. The script streams parquet batches, normalizes text, and builds a byte cache for each language.

Why Russian might help other languages

Language models do not know political borders. They learn statistical structure: characters, byte sequences, word fragments, grammar, names, document formats, and factual distributions. Russian shares some of that structure with several languages already in scope.

In this run, the strongest target-language gains appeared in Cyrillic Slavic languages. That is the pattern we would expect if Russian contributes useful shared signal rather than random noise.

What the top-line number means

The no-Russian model averaged 3.0576 BPB on the Slavic target set. Adding Russian at the same total budget reduced that to 3.0444 BPB. That is a 0.43% improvement in this proxy.

The effect is small but directionally useful, and it appears in a setup where Russian is only about 1.52% of the available language-coded mix after renormalization.

What the model sampled from

The original table had many language-specific rows. The experiment summed those rows into one target mass per language, then normalized them into probabilities. English remains the largest available language-coded slice, but many European languages are present.

Rows without language suffixes were not used for this language transfer probe. That includes generic CLM, StarCoder, OLMo, math, and generic Nemotron rows. They matter for the full production mix, but not for this narrow question.

What this does and does not prove

It does show

A controlled small-model signal that Russian improves the Slavic target average under fixed budget in this proxy.

It does not show

A final production-model result, a downstream benchmark result, or the exact best Russian ratio for the final data mix.

Best next step

Repeat with the production tokenizer, actual streamed production shards, and downstream Ukrainian/Bulgarian/Serbian/Macedonian evaluations.

Important caveat: this experiment uses FinePDFs-Edu one-shard proxy data. It matches the language weights from the allocation table where local data is available, but it is not the complete production corpus.
